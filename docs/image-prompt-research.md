# 图片提示词改进依据

查阅日期：2026-10-30。目标仍是用户配置的 `gpt-image-2`，不切换模型，不验证第三方中转站接口。

## 来源

- [OpenAI 官方 imagegen skill 的提示词规范](https://github.com/openai/skills/blob/main/skills/.system/imagegen/references/prompting.md)：详细需求应忠实整理；模糊需求只适度补充构图、光照等细节。参考图应明确编号和用途，修改需要重新声明保留项。
- [OpenAI Image prompting 指南](https://developers.openai.com/api/docs/guides/image-prompting)：画面文字、构图、身份保留、风格迁移、融合与局部修改的具体方法。该页面目前部分示例面向更新模型，文末保留 GPT Image 2 专节；示例效果不能直接当作 Image 2 的效果保证。
- [GPT Image 2 官方 Cookbook](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)：用于参考典型任务写法。旧示例中的 API 参数不照搬；本次只改变提示词流程。

没有发现能跨场景保证“最好”的通用提示词。采用可追溯的官方实践，并将本项目输入与参考图处理结合起来，比复制一段“万能画质词”更适合评估和迭代。

## 已落地

原流程：规划模型输出自由文本 prompt，直接交给图片服务。

新流程：规划与选路 → 图片路线加载 `agent-skills/image-prompt/SKILL.md` → 语言模型输出结构化说明 → 校验 → 编译最终提示词 → 原有图片服务。

说明包含用途、场景、主体、构图、视觉表现、光照材质、画面文字、参考图用途、变化、保留项和约束。无关字段可以为空，避免强行增加内容。参考图编号与实际上传顺序一致，文字素材不占图片编号，SVG 栅格化后仍占原编号。

结构、长度、参考图编号和编辑保留项进行程序校验；失败最多修复一次，仍失败则结束任务。语言模型负责检查语义上的需求冲突和文字忠实度，程序检查不能保证这一部分完全正确。最终提示词和结构化说明保存到任务方案中，用户可以查看实际提交内容。

图片路线正常情况下增加一次语言模型调用，结构修复最多再增加一次；SVG 路线不增加调用。不会新增图片调用次数，也不改图片 API 参数、地址或密钥。

## 评估

`npm run check` 包含结构修复、实际 prompt 传递、SVG/位图混合参考编号、编辑保留项、SVG 不额外调用等回归检查。

`node scripts/evaluate-prompts.mjs --live` 可以用已保存的语言模型测试人像、含准确中文/价格的海报、项目角色延续三个用例。只读取语言模型配置，只允许语言模型接口，明确禁止图片接口调用。输出 `test-results/prompt-evaluation.json`，不导出密钥。脚本会产生语言模型调用费用。

这些验证证明流程和部分提示词要求被正确执行，不能证明最终图片质量已经提升。真实出图还需在同一模型、尺寸和质量参数下，对照评估需求忠实度、文字准确性、视觉质量、参考一致性、耗时和费用；本次未调用图片中转站做 A/B 测试。

2026-10-30 实测使用 `deepseek-flash`。三例均首次通过结构检查，标题“春日上新”和价格“¥39.90”原样保留，两例无文字要求没有添加文案。初测发现旧配色和装饰干扰，随后移除草稿方案对精炼步骤的影响，强化本次配色优先规则；复测中暖黄场景保留了白色机器人、橙色围巾和黑眼睛，没有继续强制项目旧的森林绿配色。结果仍可能含未决布局选择等瑕疵，不将小样本视为普遍保证。
